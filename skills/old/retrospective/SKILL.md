# retrospective

มองย้อนทั้ง session อย่างตรงไปตรงมา เป้าหมายคือให้ผู้ใช้เรียนรู้ที่จะ **สื่อสารงานให้จบในรอบเดียว**

## กฎเหล็ก — ห้ามแต่งหลักฐาน

1. **ไม่มี transcript จริง = ไม่ทำ retro.** ถ้า session นี้เพิ่งเริ่ม หรือข้อความผู้ใช้มีแค่คำสั่งเรียก skill เอง ให้บอกตรงๆ ว่า "ยังไม่มีบทสนทนาให้ย้อนดู" แล้วหยุด ห้ามสมมติข้อความผู้ใช้ขึ้นมาเอง
2. ทุกข้อสังเกตในข้อ 1–2 **ต้องอ้างข้อความจริง** ของผู้ใช้แบบ quote ถ้า quote ไม่ได้ = ไม่ใช่หลักฐาน = ตัดทิ้ง
3. ซื่อสัตย์ ไม่ถนอมน้ำใจ แต่แยกให้ชัดว่าจุดไหนเป็น **ข้อจำกัดของ AI เอง** (มองไม่เห็นหน้าจอ, ไม่รู้ context นอกแชท, tool ล้มเหลว) ที่ **ไม่ใช่ความผิดผู้ใช้**

## โครงผลลัพธ์ (ตอบตามนี้ทุกหัวข้อ)

**0. สรุปงานนี้สั้นๆ**
- 2–3 ประโยค: session นี้ผู้ใช้ให้ช่วยทำอะไร เป้าหมายหลักคืออะไร
- ตอนจบสำเร็จระดับไหน: เสร็จ / เสร็จบางส่วน / ยังค้าง (ระบุชัด)

**1. จุดที่ผู้ใช้สื่อสารไม่ชัด / ให้ข้อมูลไม่ครบ**
- quote ข้อความจริงที่กำกวมหรือขาด context
- บอกว่า AI "เดา" อะไรไปเพราะข้อมูลไม่พอ

**2. จุดที่เข้าใจกันคนละอย่าง**
- จุดที่ AI ตีความไม่ตรงเจตนา
- รู้ตอนไหนว่าคลาด — quote ข้อความที่ผู้ใช้ต้องทักกลับ/แก้ทิศ

**3. แยกรอบ: rework vs scope ใหม่**
- แต่ละรอบที่วนกลับมา เป็น "แก้ของเดิมที่พลาด" หรือ "ผู้ใช้เพิ่ม/เปลี่ยนเป้า"
- อันไหนกันได้ด้วยการสื่อสาร อันไหนเป็นธรรมชาติของงาน (เลี่ยงไม่ได้)

**4. รอบหน้าทำยังไง — ของจริง ไม่ใช่หลักการลอยๆ**
- แต่ละจุดในข้อ 1–2 เขียน "ถ้าพิมพ์แบบนี้ตั้งแต่แรกจะดีกว่ายังไง" (ยกตัวอย่างประโยคจริง)
- ปิดท้ายด้วย **"ข้อความเปิด session ในอุดมคติ"** พร้อมก๊อปไปใช้ครั้งหน้า — ใส่ใน code block

## วิธีรวบรวมหลักฐาน

- อ่าน transcript ของ session ปัจจุบันทั้งหมด เน้นข้อความ user จริง (ไม่ใช่ system-reminder/hook)
- หาจุด "วนกลับ": ผู้ใช้แก้ทิศ, "ไม่ใช่", "จริงๆ คือ", ขอแก้สิ่งที่เพิ่งทำ
- จับคู่แต่ละรอบกับสาเหตุ: คำสั่งกำกวม / สมมติฐานผิดของ AI / scope เปลี่ยนจริง / ข้อจำกัด tool

## หลัก "เปิด session ให้จบรอบเดียว" (ใช้เขียนข้อ 4)

ข้อความเปิดที่ดีควรมี: **เป้าหมาย + ผลลัพธ์ที่ต้องการ (definition of done) + ขอบเขต (ทำอะไร/ไม่ทำอะไร) + ที่อยู่ไฟล์/บริบทที่เกี่ยวข้อง + ข้อจำกัด/ของที่ห้ามแตะ + รูปแบบผลลัพธ์**
